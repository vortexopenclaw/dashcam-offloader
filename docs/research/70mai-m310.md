# 70mai M310 — Research Notes

## Sources

- Official manual: [70maiDashCam_M310_UserManual.pdf](https://cdn-www.70mai.com/instructions/70maiDashCam_M310_UserManual.pdf) (V2025.12, multilingual)
- NAS footage: 47 driving clips (`NO` prefix) + 9 parking clips (`LA` × 8, `NO` × 1)
- No direct microSD card scan

## Manufacturer

70mai Co., Ltd., Shanghai, China. M310 is an entry-level single-channel front dashcam
with Wi-Fi and voice control. App required for live view and settings adjustment.

## Filename Pattern

Pattern: `[MODE]YYYYMMDD-HHMMSS-SEQUENCE.mp4`

| Field | Format | Example |
|---|---|---|
| Mode prefix | 2 uppercase letters | `NO`, `LA` |
| Date | `YYYYMMDD` | `20260206` |
| Separator | `-` | |
| Time | `HHMMSS` | `141441` |
| Separator | `-` | |
| Sequence | Zero-padded integer (6+ digits) | `000062` |
| Extension | `.mp4` (lowercase) | |

Full example: `NO20260206-141441-000062.mp4`

### Mode Prefixes

| Prefix | Mode | Confirmed |
|---|---|---|
| `NO` | Normal/continuous recording | ✅ observed in driving + parking |
| `LA` | Time-lapse parking mode | ✅ observed in parking clips |
| `EM` | Emergency/locked clip | ❓ inferred from manual; no sample |

### Key Differences from VIOFO

- **Lowercase `.mp4`** vs VIOFO uppercase `.MP4`
- **Date-hyphen-time** format vs VIOFO `YYYY_MMDD_HHMMSS` with underscores
- **Mode prefix at start** vs VIOFO channel/sequence at end
- **No channel letter** — single camera only

## Sequence Numbers

- Scope: global across all modes (NO and LA share the same counter)
- Padding: 6 digits zero-padded
- NAS sample range: 62–1732 (56 files, non-contiguous — only notable clips archived)
- Confirmed sequential within each session by date/time cross-check

## Resolution and Codec

| Channel | Resolution | Codec | FPS | Segment |
|---|---|---|---|---|
| Front | 2304×1296 | HEVC (H.265) | 30 | 60 s |

Manual specification: "Resolution: 2304 × 1296". Confirmed by ffprobe on all NAS samples.

No rear or interior channel — single-channel camera.

## OSD Analysis

The M310 burns **date/time** into the bottom of every frame in the format:
```
MM-DD-YYYY HH:MM:SS | [additional data]
```

OCR result example: `02-08-2026 20:10:16 | Se`

**Key finding**: The OSD does **not** embed the model name. This is fundamentally
different from VIOFO cameras (which show "VIOFO A229 Pro" etc.) and means OCR-based
model identification is not possible for 70mai cameras using this approach.

The `|` separator is followed by what may be GPS speed or another data field; OCR
output was truncated in tests. The date format `MM-DD-YYYY` matches North American
convention.

Daytime footage with complex scenes (e.g. highway backgrounds) produced OCR noise
because OSD text blends with high-contrast road/sky backgrounds. Night footage gave
clean OCR reads.

## Folder Structure

Not directly confirmed from a card scan. Inferred from 70mai product conventions:

| Folder | Contents |
|---|---|
| `Normal/` | Loop recording (driving) |
| `Parking/` | Parking mode clips (time-lapse and normal) |
| `Emergency/` | Locked/impact clips |

The NAS footage was pre-organized by the user into separate directories with
descriptive filename labels; this does not reflect the on-card folder structure.

## Detection Strategy

No single uniquely identifying signal. Best approach is a combination:

1. **Filename pattern** (primary): `^(NO|LA|EM)\d{8}-\d{6}-\d+\.mp4$` — distinctive
   two-letter prefix + date-hyphen-time scheme not used by VIOFO, Thinkware, BlackVue, or Vantrue
2. **File extension** (supporting): lowercase `.mp4` (rules out VIOFO)
3. **Resolution** (supporting): 2304×1296 HEVC 30fps
4. **OSD** (negative signal only): absence of VIOFO/Thinkware/BlackVue brand text in OSD

Within 70mai's lineup, different models may share this filename scheme. The M310
is a 1CH camera — presence of multi-channel files with this pattern would suggest
a different 70mai model.
