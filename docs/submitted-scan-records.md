# Submitted scan records

Only explicit feedback submissions already stored by the feedback Worker are ingested. A local card scan without submission consent is never uploaded. The Worker remains write-only; no unauthenticated listing route is added. A webhook would require a new authenticated delivery channel, retry queue and deploy. A read-only Cloudflare KV pull via the existing maintainer API credentials is simpler and survives missed runs. Launchd polls every 15 minutes while this Mac user is logged in; it is **not** instantaneous and not a cloud service.

`scripts/ingest-submitted-scans.py` pages through KV feedback keys, filters submission UUID keys, ignores feedback without a scan, and writes one private JSON projection per key. Records live outside the git repository under the active Hermes profile's `submitted-scans/` directory, with restricted permissions. Repeated runs do not overwrite a key. New model fields, media/channel/mode counts, measured video-spec groups and bounded camera-shaped media basenames are retained. Contacts, messages, paths, arbitrary names, raw submissions and unrecognized fields are discarded. Unknown channels and unconfirmed parking subtype are review flags, not inferred facts. Existing records are immutable snapshots; a changed submission under an existing key is not reprocessed. This is local evidence staging, **not** automatic profile updates or public documentation publication.

The app sends up to 100 distinct camera-shaped media basenames in an opt-in feedback scan. The Worker revalidates them and discards arbitrary path or personal names. Existing stored submissions have no filenames; they cannot be retroactively reconstructed. The profile's inferred parking filename tokens and folder paths still need card evidence.

Run manually: `python3 scripts/ingest-submitted-scans.py`. Test: `python3 -m unittest discover -s scripts -p test_ingest_submitted_scans.py` and `node --test workers/feedback/worker.test.mjs`. The local launch agent `com.vortexradar.dashcam-submitted-scans` points at this dedicated worktree and must be updated or disabled if the worktree is removed. Inspect `launchctl print gui/$(id -u)/com.vortexradar.dashcam-submitted-scans` to confirm activation. The job uses the existing OpenClaw environment loader and does not embed credentials in the plist.
